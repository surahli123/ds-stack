# 3p 高频用户的实验回溯分析讨论稿

整理日期：2026 年 11 月 11 日  
状态：分析方案讨论稿，尚未运行数据分析  
用途：与业务、Data Science 和实验负责人讨论，确定分析口径及下一步数据工作

## 本次要回答的问题

一次 L1 search ranking model 升级是否对**历史上更频繁使用 3p 搜索的用户**造成了更大的 3p 搜索活跃度损失？这是对已结束实验的 retrospective analysis，回应 leads 关于 tradeoff 是否 disproportionately 影响 3p power user 的问题。

建议使用实验前的 3p 搜索点击历史固定用户分组，再比较原实验期间各组的 treatment 与 control。第一版以历史活跃天数的 P80 定义“历史 3p 高频组”，作为 power user 的操作性候选。分析同时报告绝对与相对效应，并直接比较高频组与轻度组的效应差。

**当前已形成可进入数据核查的方案，但没有得到实验结论。**P80 是否能分出有意义的人群、原实验设计是否支持当前估计，以及“更不成比例”应以哪种效应尺度为主，仍需在公司环境确认。

## 事件背景与证据状态

| 类型 | 当前掌握的信息 | 对分析的含义 |
| --- | --- | --- |
| 事件背景 | 曾出现 3p DAU 显著下降的 SEV，初步 RCA 指向一次 relevance launch | 需要回溯该 launch 对 3p 搜索用户的影响 |
| 已回顾的线索 | 时间吻合，且 Statsig scorecard 在实验运行期间出现 3p relevance signal | 需要核查原指标与 T/C 结果；目前不能写成已确认的 3p search DAU treatment effect |
| 改动内容 | 升级了 L1 search ranking model | 明确原实验版本、assignment 和观察窗口 |
| 机制假设 | 模型可能更 favor 1p content，减少 3p connector app 内容的展示 | 这是待验证机制；仅看点击变化无法证明 |
| 使用背景 | 用户主要寻找 1p 内容，也有部分 3p 搜索需求，例如查找 Confluence 内容 | 不应把所有 3p 用户描述成主要依赖 3p 的用户 |
| 数据特征的回顾 | 3p 点击较稀疏，很多用户在 DAU 或 MAU 窗口内只有一次点击，先前实验分析感觉噪音较大 | 先看活跃天数分布和高频尾部，再判断分组是否可用 |
| 当前缺失 | 实际数据、实验日期、随机化单位、样本量及完整实验配置 | 暂不能计算效应、区间或判断是否存在异质性 |

本次只研究 **3p search DAU，按用户点击 3p 搜索结果计算**。不纳入 chat 或 AI search 中由系统生成的 3p 引用。

## 已达成的分析选择

1. 用处理前的历史行为分组，实验期间不重新划分用户身份。
2. 接受 P80 作为第一版候选阈值；先核查其实际含义，再看各组实验效应。
3. 保留三个历史组：高频、轻度、窗口内未活跃。
4. 以固定用户的实验期 3p 点击活跃天数衡量与 DAU 对应的结果，包括零点击用户。
5. 比较各组原实验的 T/C，直接估计高频与轻度的效应差及其不确定性。
6. 同时保留绝对与相对尺度，尚未决定哪一个是主判据。

研究对象仍是用户。Statsig 是实验平台，不能据此推断随机化单位或将问题改成 tenant-level 研究。

## 历史分组的数学定义

### 历史活跃天数

设固定历史窗口为 \(W\)，其所有日期均早于此次处理的首次影响；\(c_{u,t}\) 表示用户 \(u\) 在日期 \(t\) 的 3p 搜索结果点击次数。定义：

\[
D_u=\sum_{t\in W}\mathbf{1}(c_{u,t}>0)
\]

\(D_u\) 衡量历史窗口内有多少天发生过 3p 搜索点击，同一天多次点击只计一个活跃日。历史窗口长度仍待确认，不能把某个天数当成已确定设置。

### P80 阈值与三个固定组

在同一个待分析实验人群中，仅使用历史记录完整且 \(D_u>0\) 的用户，合并两臂的处理前数据计算统一阈值：

\[
q_{80}=P80\bigl(\{D_u:D_u>0\}\bigr)
\]

| 历史分组 | 条件 | 本次解释 |
| --- | --- | --- |
| 历史 3p 高频组 | \(D_u\ge q_{80}\) | power user 的第一版操作性候选 |
| 历史 3p 轻度组 | \(0<D_u<q_{80}\) | 有历史 3p 点击，但活跃天数较少 |
| 历史窗口未活跃组 | \(D_u=0\)，且历史观察完整 | 该窗口没有 3p 点击；不能据此断言从未使用过 3p |

阈值不在 treatment 和 control 内分别计算。实验期开始点击的用户保留原历史身份，例如历史未活跃用户即使实验期成为 3p DAU，也仍属于历史未活跃组。

### 看效应之前先核查定义

需要先输出：P80 对应的实际活跃天数、阈值处并列人数、各组人数和占比，以及高频与轻度组的活跃天数分布。固定分位数算法，并记录阈值参考人群。

- 保留阈值处并列，因此高频组未必恰好占历史活跃用户的 20%。
- 如果 \(q_{80}=1\)，所有历史活跃用户都会进入高频组，轻度组为空；这个定义无法回答高频与轻度的比较，需重新讨论定义，不能随意拆散并列。
- 账号尚不存在、历史日志缺失、观察期不完整的用户，不能直接归为 \(D_u=0\)。需要单独记录并明确纳入规则。
- 如果历史足够，可以查看更早等长窗口中的使用情况，辅助理解分组稳定性；这不是当前分析的必需步骤，也不自动改变分组。

**高频点击不等于更依赖 3p。**这个定义能够回答“历史更频繁点击 3p 的用户是否损失更多活跃度”，尚不能直接回答“最需要 3p 的用户是否受损最多”。在定义的业务含义得到确认前，使用“历史高频组”或“power 候选”的表述。

## 在原实验期间估计效应

### 分析人群与结果

分析人群按原实验设计及不受此次处理影响的资格规则确定。不能只纳入实验期间点击过 3p、发生过搜索或成功激活的用户。如果纳入资格依赖实验期行为，需要先判断该行为是否可能被 treatment 改变。

以下表达以**用户具有稳定的 T/C assignment，并在共同窗口内可比地观察**为前提。设共同实验观察期为 \(M\) 天：

\[
Y_u=\frac{\sum_{t\in\text{实验观察期}}\mathbf{1}(c_{u,t}>0)}{M}
\]

\(Y_u\) 是每位固定用户平均每天成为 3p search DAU 的比例；零点击用户的结果为零。共同观察期内，\(M Y_u\) 就是该用户的 3p 搜索活跃天数。日志缺失必须与真实零点击区分。

### 各组效应与组间差异

对历史组 \(g\)，令 \(p_{g,T}\) 和 \(p_{g,C}\) 为该组 treatment 与 control 的 \(Y_u\) 均值：

\[
\Delta_g=p_{g,T}-p_{g,C},\qquad
R_g=\frac{p_{g,T}-p_{g,C}}{p_{g,C}}
\]

| 尺度 | 回答的问题 | 解读 |
| --- | --- | --- |
| 绝对效应 \(\Delta_g\) | 平均每位用户每天少了多少点击活跃概率 | \(M\Delta_g\) 对应每用户平均活跃天数的变化 |
| 相对效应 \(R_g\) | 相对于该组实验期 control 水平，变化了多少比例 | 分母是实验期 control 均值，不是历史点击率 |

直接估计以下高频与轻度的效应差及其区间：

\[
\Gamma_{\mathrm{abs}}=\Delta_{\mathrm{高频}}-\Delta_{\mathrm{轻度}}
\]

\[
\Gamma_{\mathrm{rel}}=R_{\mathrm{高频}}-R_{\mathrm{轻度}}
\]

两种尺度可能给出不同的异质性判断。因此，需要说明 leads 所说的 disproportionately 是平均每用户损失更多活跃天数，还是相对于各组自身 control 水平下降更多。当前两者都报告，不默认相对效应优先。

解释时遵循以下边界：

- “高频组显著、轻度组不显著”不能代替直接检验组间效应差。
- 声称高频组“受损更多”，需要同时查看高频组自身效应的方向及其不确定性。组间差更负，也可能只是两组都改善而高频组改善较少。
- 当 \(p_{g,C}=0\) 时相对效应无定义，接近零时百分比可能很不稳定。
- 区间估计必须尊重原实验随机化与用户内重复观察的相关性，不能把所有 user-days 当成独立样本。置信水平和具体估计方法按实际实验设计确定。

### 历史未活跃用户单列

在整个历史未活跃组中，比较实验期至少出现一次 3p 搜索点击的发生率：

\[
Z_u=\mathbf{1}\left(\sum_{t\in\text{实验观察期}}c_{u,t}>0\right)
\]

这保留了实验期间开始点击的用户，也保留未开始点击的用户。不能仅比较成功激活者。没有更长历史时，将其称为“历史窗口未活跃用户的实验期点击发生率”，避免把首次激活与重新活跃混为一谈。

实验中途新进入的用户是否属于当前分析人群，需要根据原纳入规则和可观察窗口另行确认。

### 一个补充诊断

补充查看每位固定用户的实验期 3p 搜索点击总次数，仍保留零点击用户，用于判断日内二值指标是否遗漏下降。同一天从多次点击降到一次，不改变 DAU；从一次降到零次才损失一个活跃日。

这个诊断不替代 DAU，也不直接证明可见性下降。

## 因果解释与结论边界

实验已经结束，不妨碍利用保存的随机 assignment 和同期 control 开展回顾分析。若原随机设计、纳入规则和测量有效，处理前固定组内的 T/C 比较可估计组平均处理效应；比较组间效应是探索性的 heterogeneous treatment effects 分析。

因果解释来自原实验设计。需要先确认：

1. scorecard 对应的实验版本、运行和 ramp 时间，以及此次改动的真实处理边界。
2. 原始 assignment 是否可恢复，随机化单位、分配概率及处理分配是否在分析期内稳定。
3. 历史与结果窗口是否可比，点击埋点是否一致，缺失或日志变更是否影响两臂。
4. 分组、分析人群或曝光筛选是否受到 treatment 影响，以及原实验是否有已知完整性问题。

如果实际按 tenant 随机，仍可研究用户平均效应，但推断必须保留 tenant 内相关性，并避免无意改成平均 tenant 效应。如果按 query 或 session 分配，同一用户可能经历两臂，需要先调整当前的处理与结果定义；仅增加聚类标准误不足以修复处理定义。

本次是由 RCA 引出的事后探索，不能称为原实验预设假设。记录尝试过的窗口、阈值与指标，不根据显著性挑选报告。当前不需要为了增加方法复杂度而引入 causal forest、PSM、DiD 或 QTE；如原随机记录不可用，需重新讨论可支持的分析范围。

即使发现高频组点击活跃度损失更大，也不能仅凭该结果证明“favor 1p → 3p 展示减少 → 用户找不到内容”的机制，或证明“成为 power user 导致更大伤害”。机制问题需要另外的曝光、排名或相关性证据。

## 带回公司需要确认的事项

| 待确认项 | 需要带回的信息或决定 | 用途 |
| --- | --- | --- |
| 原实验设计 | 实验 ID、版本、日期、assignment、随机化单位与已知完整性问题 | 确定处理定义与推断方式 |
| 分析人群 | 原纳入规则、稳定身份、历史完整性及中途进入用户的处理 | 固定可解释的分析对象 |
| 历史窗口 | 处理前窗口 \(W\)、数据覆盖与分位数算法 | 固定可复现的历史分组 |
| P80 的实际含义 | 阈值天数、并列人数、各组占比和分布 | 判断是否真的分出了高频与轻度 |
| 结果窗口和点击口径 | 共同观察期 \(M\)、3p search 点击事件、缺失规则 | 确认结果对应本次 DAU 问题 |
| 业务主判据 | 更关心每用户活跃天数损失，还是比例侵蚀 | 选择绝对或相对组间差作为主判据 |

建议先产出一张分组定义核查表，再产出效应结果表。结果表至少包括：历史组、T/C 用户数、control 基线、绝对效应及区间、相对效应及区间。另列高频与轻度的直接效应差及区间；历史未活跃组的点击发生率单列。现阶段所有数值均待数据分析后填写。

最终读数应能回答：**哪一组、在哪种尺度上、相对于什么基线、受到多大影响，以及估计有多大不确定性。**如果区间很宽，应明确证据不足，不能写成没有影响。
